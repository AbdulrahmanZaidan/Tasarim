# DBG-8 — debuggability-first design proposal (ISA v0 + datapath + control unit)

STATUS: COMPLETE (sections 0-10 + Appendix A)

## 0. Key decisions (skeleton)
1. **4-phase cycle** from a master clock MCLK = 4 x CPU clock (4 MHz crystal -> 1 MHz CPU; 8 MHz -> 2 MHz). A 2-FF Johnson counter (74HC74) gives phases A,B,C,D. All CPU registers commit on ONE edge (B->C = CLK rising) using synchronous enables; the control word is latched at C->D (74HC273, cleared to an all-zero NOP word by reset); the memory/IO write strobe exists only in phase A (never next to an edge where the address or data can change).
2. **Stops only at cycle boundaries**: RUN/STOP, single-step (micro-step or whole instruction), HALT, breakpoint and BUSREQ all freeze the phase counter in phase C, so a cycle can never be cut in half. A VRAM write outside vertical blanking freezes the counter in phase D (wait state) instead of silently dropping the write.
3. **Programmer's model**: A (8-bit accumulator), X (16-bit pointer, post-increment), SP (8-bit, stack page EF00-EFFF), PC (16), flags Z C N V. Hidden: IR, AR (16-bit operand/target address), 4-bit step counter.
4. **Buses**: 8-bit data bus DB with a 3-bit source field (74HC138) and a 3-bit destination field (74HC138) -> two drivers can never fight; 16-bit address bus AB with 4 sources (PC, AR, X, SP) selected by a 2-bit field (74HC139). All drivers are 74HC245 (DIR tied). 10k pull-downs on DB (undriven DB reads 00), pull-ups on AB.
5. **ALU = 2 x SST39SF010A nibble lookup ROMs** (A op DB -> A, flags Z C N V), op = 5-bit field; tables generated from isa.yaml, so emulator and hardware share the same truth table bit-for-bit.
6. **Microcode**: 3 x SST39SF010A (24-bit control word, 23 used + 1 scope-marker bit), address = flags(4) + opcode(8) + step(4); fetch is ONE step; every undefined opcode and 0x00/0xFF HALT.
7. **Manual control panel**: 24 DIP switches feed the *inputs* of the control latch when the microcode ROMs are output-disabled, so manual words go through the same latch/timing as real microcode; 8 data switches are a data-bus source.
8. **Memory/IO**: ROM 0000-7FFF, RAM 8000-EFFF (stack page EF), VRAM F000-F7FF write-only, IO F800-FFFF (8 registers, mirrored).
9. **VGA**: 12.5875 MHz dot clock, counters 74HC163, sync/blank/window decode in a timing flash; counters step mid-character, all pipeline registers load at the character boundary, so pixels and sync/blank are aligned without table offsets (section 7).
10. **PS/2**: fully synchronous receiver (oversampled by the free-running 4 MHz crystal oscillator), bit counter + 74HC377 shift register, READY flag; keyboard is inhibited (KCLK held low) while READY=1, so no byte can be lost or change while the CPU reads it. Arduino Mega = optional trace/loader via BUSREQ; never needed for the demo.
11. **C**: static (compiled-stack) locals/params, no recursion; hardware stack only for return addresses and save/restore.

Design rule behind every choice below: **one commit edge, one write window, no partial cycles, every register on LEDs, every module testable alone with DIP switches before microcode exists, and every table (microcode, ALU, VGA timing, font) generated by Python from one source.**

### 0.1 Deviations from the agreed baseline (and why)
| Baseline | This design | Why |
|---|---|---|
| Control word latched on the falling clock edge, registers on the rising edge | 4-phase cycle from a 4x master clock: latch at C->D, commit at B->C, /WE only in phase A | /WE gets a full phase of address setup and hold by construction; stops and BUSREQ happen at a clean cycle boundary; the VRAM stall has a place to wait (phase D); the 74HC191 "change controls only while CP high" rule is met for free. Cost: 1x 74HC74 + 1x 74HC00. |
| 4-bit DB source field into a 74HC154 | 3-bit DSRC into a 74HC138 (7 sources + none) and a 3-bit DDST 138 | Only 7 sources are needed; TI's DIP 74HC154 is obsolete and costs ~116 TL in Turkey vs ~11 TL for a 138. Same "never two drivers" guarantee. |
| "Hardware blocks CPU writes outside the VRAM window" | Hardware **stalls** the write (phase D wait) until the window opens | A blocked write is silently lost, which is a debugging nightmare; a stall is always correct and the WAIT LED shows it. |
| Vertical blanking window ~1.43 ms (45 lines) | Write window = lines 482-522 (41 lines, 1.30 ms) inside a VRAM-mux window 481-523 | One line of guard on each side makes the clock-domain crossing provably safe (section 6.3). |
| uROM address = opcode + step + flags | + A16 = BANK jumper | Two microcode versions per chip set (known-good / experimental). |
| (unspecified) ALU | 2 nibble-sliced flash lookup ROMs | 2 chips, all 20 ops incl. shifts and V, identical to the emulator's table. |
| (unspecified) bus buffers | 74HC245 with DIR strapped instead of 74HC541 | Same function, ~1/4 of the local price. |
| PS/2 synchronized to the CPU clock | PS/2 receiver in its own free-running 4 MHz domain, READY crossed by a 2-FF synchronizer | Keyboard keeps working while the CPU is single-stepped or on the 555. |

## 1. Programmer's model

| Register | Width | Visible? | Notes |
|---|---|---|---|
| **A** | 8 | yes | Accumulator. The only ALU destination: `A <- ALU(A, DB)`. |
| **X** (XH:XL) | 16 | yes | Pointer register. Load immediate/absolute, store absolute, post-increment, byte moves to/from A, push/pop. |
| **SP** | 8 | yes (implicit) | Stack pointer inside the fixed stack page **EFxx** (top 256 bytes of RAM). Changed only by PHA/PLA/PHX/PLX/CALL/RET and by reset. |
| **PC** | 16 | yes (via jumps) | Reset value 0000. |
| **F** = Z C N V | 4 | yes (via branches, ADC/SBC/ROL/ROR) | Not readable as a byte (no interrupts, so no need to save them). |
| IR | 8 | hidden | Opcode; part of the microcode address. |
| AR (ARH:ARL) | 16 | hidden | Operand address / jump target, built byte by byte from the instruction stream; can increment. `PC <- AR` is a 16-bit parallel load. |
| STEP | 4 | hidden | Micro-step counter (max 16 steps per instruction). |

**Flags** (6502 conventions, so the compiler writer can use 6502 literature):
- **Z** result = 0; **N** = result bit 7; **C** = carry out of ADD/ADC; for SUB/SBC/CMP **C = NOT borrow** (C=1 means A >= operand, unsigned); shifts put the shifted-out bit in C; **V** = signed overflow of ADD/ADC/SUB/SBC/CMP/NEG.
- Loads and logic ops change only Z and N (C and V preserved), so a multi-byte sequence `ADD lo / STA / LDA hi / ADC hi` keeps its carry. INC/DEC change only Z,N. Which flags an op changes is decided by the ALU ROM table (the ROM receives the old C and V and passes them through), not by extra hardware.

**Addressing modes** (16-bit quantities are little-endian):
| Mode | Syntax | Bytes after opcode | Used for |
|---|---|---|---|
| implied / accumulator | `INC`, `RET` | 0 | unary A ops, stack, control |
| immediate 8 | `#n` | 1 | constants |
| immediate 16 | `LDX #nn` | 2 | pointer constants |
| absolute | `addr` | 2 | globals, static locals/params, memory-mapped I/O |
| X-indirect | `(X)` | 0 | `*p`, arrays after the compiler forms the address in X |
| X-indirect post-increment | `(X+)` | 0 | string/array walks, `*p++` |
| stack (implicit SP) | `PHA` ... | 0 | return addresses, save/restore |
| absolute target | `JMP/CALL/Bcc addr` | 2 | all control transfers (no relative branches -> no address adder) |

Deliberately absent: base+offset (indexed) and SP-relative modes. Both need a 16-bit address adder (4x 74HC283 + muxes) and add a timing path; with static C frames (section 9) the compiler does not need them.

**Stack**: empty-descending in page EF: `push = write [EF:SP], SP-1`; `pop = SP+1, read [EF:SP]`. Reset sets SP = FF, so the first byte goes to EFFF. 256 bytes = 128 nested calls.

**Reset state**: PC=0000, SP=FF, X=0000, AR=0000, F=0000, STEP=0, control word = all-zero NOP. A and IR are undefined; the first fetch loads IR, and the emulator/trace-diff treats A as "unknown until first written".

**Memory map**: 0000-7FFF ROM (SST39SF010A, low 32K) | 8000-EFFF RAM (AS6C62256, 28K; EF00-EFFF = stack) | F000-F7FF VRAM, write-only, `F000 + row*64 + col` | F800-FFFF I/O, 8 registers mirrored every 8 bytes (section 6).

## 2. Instruction set (ISA v0)

### 2.1 Opcode encoding (chosen so the 8 IR LEDs are readable by eye)
| Range | Group | Encoding |
|---|---|---|
| `00` | HALT | also every undefined opcode and `FF` (erased flash / zeroed RAM halts instead of running wild) |
| `01` | NOP | |
| `40-67` | **M**: memory/ALU | `0100_0000 + op*4 + mode`; op: 0 LDA, 1 STA, 2 ADD, 3 ADC, 4 SUB, 5 SBC, 6 AND, 7 OR, 8 XOR, 9 CMP; mode: 0 `#n`, 1 `abs`, 2 `(X)`, 3 `(X+)`. (`44` = STA # is undefined -> HALT) |
| `80-8B` | **U**: unary on A | 80 INC, 81 DEC, 82 NOT, 83 NEG, 84 SHL, 85 ROL, 86 SHR, 87 ROR, 88 ASR, 89 TST, 8A CLC, 8B SEC |
| `90-97` | **X** ops | 90 LDX #nn, 91 LDX abs, 92 STX abs, 93 INX, 94 TAXL (XL<-A), 95 TAXH (XH<-A), 96 TXLA (A<-XL), 97 TXHA (A<-XH) |
| `A0-A7` | **S**: stack/flow | A0 PHA, A1 PLA, A2 PHX, A3 PLX, A4 JMP abs, A5 JPX (PC<-X), A6 CALL abs, A7 RET |
| `B0-BD` | **B**: branch abs | `B0 + cond` (table 2.3) |

**Count: 53 mnemonics = 83 opcodes** (2 + 39 + 12 + 8 + 8 + 14). The microcode generator fills all other 173 opcodes with the "illegal" sequence (HALT + MARK bit set), so the IR LEDs show the bad opcode and PC points just past it.

### 2.3 Branch conditions (decided in microcode: the 4 flags are microcode-ROM address bits, so no condition multiplexer exists)
| cc | Mnemonic | Condition | Use |
|---|---|---|---|
| 0/1 | BEQ / BNE | Z / !Z | == != |
| 2/3 | BCS=BHS / BCC=BLO | C / !C | unsigned >= / < |
| 4/5 | BMI / BPL | N / !N | sign |
| 6/7 | BVS / BVC | V / !V | |
| 8/9 | BLT / BGE | N!=V / N==V | **signed** < / >= |
| A/B | BGT / BLE | !Z & N==V / Z or N!=V | signed > / <= (8-bit only) |
| C/D | BHI / BLS | C & !Z / !C or Z | unsigned > / <= (8-bit only) |

For 16-bit compares Z only describes the high byte, so the compiler emits `a > b` as `b < a` (operands swapped, BLT/BLO) - no "Z-chaining" hardware needed.

### 2.4 Exact micro-step sequences
Field names are those of the control word (section 4.2); shorthands: PC+ = PCINC, AR+ = ARINC, X+ / [X+] = XINC (only in the (X+) mode), SP+ = SPCNT, SP- = SPCNT+SPDN, ALU=op = ALUOP, DSRC=- = none. Unlisted fields are 0. Step 0 is identical for all 256 opcodes and all 16 flag values.

```
S0  FETCH (all)   ASRC=PC  DSRC=MEM  DDST=IR  PC+
--- group M, mode #n -----------------------------------------------------------
S1  LDA/ALU #     ASRC=PC  DSRC=MEM  DDST=A   ALU=op  FL  PC+  NEXT     (CMP: no DDST)
--- group M, mode abs ----------------------------------------------------------
S1                ASRC=PC  DSRC=MEM  DDST=ARL PC+
S2                ASRC=PC  DSRC=MEM  DDST=ARH PC+
S3  LDA/ALU       ASRC=AR  DSRC=MEM  DDST=A   ALU=op  FL  NEXT
S3  STA           ASRC=AR  DSRC=A    MEMW     NEXT
--- group M, mode (X) / (X+) ---------------------------------------------------
S1  LDA/ALU       ASRC=X   DSRC=MEM  DDST=A   ALU=op  FL  [X+]  NEXT
S1  STA           ASRC=X   DSRC=A    MEMW     [X+]  NEXT
--- group U --------------------------------------------------------------------
S1  INC..ASR      DSRC=-   DDST=A    ALU=op   FL  NEXT     (TST/CLC/SEC: no DDST)
--- group X --------------------------------------------------------------------
LDX #nn  S1 ASRC=PC DSRC=MEM DDST=XL PC+ | S2 ASRC=PC DSRC=MEM DDST=XH PC+ NEXT
LDX abs  S1,S2 as abs | S3 ASRC=AR DSRC=MEM DDST=XL AR+ | S4 ASRC=AR DSRC=MEM DDST=XH NEXT
STX abs  S1,S2 as abs | S3 ASRC=AR DSRC=XL MEMW AR+     | S4 ASRC=AR DSRC=XH MEMW NEXT
INX      S1 X+ NEXT
TAXL     S1 DSRC=A DDST=XL NEXT            (TAXH: DDST=XH)
TXLA     S1 DSRC=XL DDST=A ALU=PASSB FL NEXT   (TXHA: DSRC=XH)
--- group S --------------------------------------------------------------------
PHA   S1 ASRC=SP DSRC=A  MEMW SP- NEXT
PLA   S1 SP+ | S2 ASRC=SP DSRC=MEM DDST=A ALU=PASSB FL NEXT
PHX   S1 ASRC=SP DSRC=XH MEMW SP- | S2 ASRC=SP DSRC=XL MEMW SP- NEXT
PLX   S1 SP+ | S2 ASRC=SP DSRC=MEM DDST=XL SP+ | S3 ASRC=SP DSRC=MEM DDST=XH NEXT
JMP   S1,S2 as abs | S3 PCLD NEXT
JPX   S1 DSRC=XL DDST=ARL | S2 DSRC=XH DDST=ARH | S3 PCLD NEXT
CALL  S1,S2 as abs | S3 ASRC=SP DSRC=PCH MEMW SP- | S4 ASRC=SP DSRC=PCL MEMW SP- PCLD NEXT
RET   S1 SP+ | S2 ASRC=SP DSRC=MEM DDST=ARL SP+ | S3 ASRC=SP DSRC=MEM DDST=ARH | S4 PCLD NEXT
--- group B (flags are in the uROM address) ------------------------------------
taken      S1,S2 as abs | S3 PCLD NEXT
not taken  S1 PC+ | S2 PC+ NEXT
--- misc -----------------------------------------------------------------------
NOP        S1 NEXT
HALT       S1 HALT NEXT
illegal    S1 HALT MARK NEXT
```
Why "write + modify the address register in the same step" (STA (X+), STX S3, PHA, CALL S4) is safe: the write strobe exists only in phase A; registers change at the B->C edge, a full phase after /WE has gone high (section 5). The microcode generator still checks two rules for every word: (1) at most one DB source and one DB destination (guaranteed by the encoding), (2) a MEMW step never has DSRC=MEM or DSRC=- .

## 3. Datapath

### 3.1 Clock names used below
- **MCLK** = master clock (4 MHz for a 1 MHz CPU). **Phases** A,B,C,D from a 2-FF Johnson counter (section 5).
- **CLK** = CPU commit clock = Johnson Q2: **rises at B->C** (the only edge on which any CPU register changes), falls at D->A. CLK is HIGH during C and D.
- **LCLK** = control-latch clock = /Q1: rises at **C->D** (the control word changes here, while CLK is HIGH - required by the 74HC191 SP counter, see 3.3).
- **WSTB** = write strobe = phase A only.

### 3.2 Buses
| Bus | Width | Driven by | Selection | Undriven state |
|---|---|---|---|---|
| **DB** data | 8 | MEM, A, XL, XH, PCL, PCH, SW (panel switches) | DSRC (3 bits) -> 74HC138 #DS; G1=1, /G2A=BUSACK, /G2B=GND. Y0 = "none" (unconnected) | 10k pull-down SIP -> reads **00** (deterministic: the emulator models "no source" as 00, so trace diffs stay exact) |
| **AB** address | 16 | PC, AR, X, SP (EF:SP) | ASRC (2 bits) -> 74HC139 half #AS; /G=BUSACK | always driven by exactly one source except during BUSACK; 10k pull-up SIPs so an idle bus reads FFFF |
| ALU-B | 8 | = DB (ALU B input wired to DB permanently) | - | - |
| internal | 16 | AR outputs -> PC parallel-load inputs (not via DB) | PCLD | - |

All bus drivers are **74HC245 with DIR tied high (A->B)**, /OE from a decoder output. (74HC541 has the nicer flow-through pinout but costs ~4x the 245 at Turkish shops; a strapped 245 is functionally identical.) Only decoder outputs drive bus-driver /OE pins, so two DB drivers or two AB drivers can never be on together - by construction, not by microcode discipline.

### 3.3 Registers
| Reg | Parts | Load | Inc/Dec | Reset | Outputs go to |
|---|---|---|---|---|---|
| **PC** | 4x 74HC161 (sync /LOAD, async /MR, CEP/CET enables, TC chain) | PCLD: all 16 bits from **AR outputs** on CLK^ | PCINC -> CEP of all four, CET chained from TC | /MR=/RESET -> 0000 | AB (2x245), DB as PCL/PCH (2x245), 16 LEDs |
| **AR** | 4x 74HC161 | from DB: low pair /LOAD=/DD_ARL, high pair /LOAD=/DD_ARH | ARINC (16-bit) | /MR -> 0000 | PC D-inputs, AB (2x245), 16 LEDs |
| **X** | 4x 74HC161 | from DB: low pair /LOAD=/DD_XL, high pair /LOAD=/DD_XH | XINC (16-bit) | /MR -> 0000 | AB (2x245), DB as XL/XH (2x245), 16 LEDs |
| **SP** | 2x 74HC191 (sync up/down count, **async** parallel load) | none from the bus; D0-D3 tied high, /PL=/RESET -> async load **FF** | /CE_lo = NOT SPCNT; /CE_hi = NAND(SPCNT, TC_lo); U/D = SPDN (0 up, 1 down) | /PL -> FF | AB low byte (245); AB high byte = 2nd 245 with inputs strapped to **EF**; 8 LEDs |
| **A** | 74HC377 (8 D-FF, sync /E) | D = ALU result, /E=/DD_A | via ALU (INC/DEC) | none (undefined) | ALU-L/H A inputs, DB (245), 8 LEDs |
| **IR** | 74HC377 | D = DB, /E=/DD_IR | - | none (step 0 ignores IR) | uROM address, 8 LEDs |
| **F** (Z C N V) | 74HC161 used as a 4-bit register (CEP=CET=0) | D = ALU-H flag outputs, /LOAD = NOT FL | - | /MR -> 0000 | uROM address, ALU (old C, old V), 4 LEDs |
| **STEP** | 74HC161 | /LOAD = NOT NEXT, D=0000 (sync return to step 0) | counts on every CLK^ (CEP=CET=1) | /MR -> 0 | uROM address, 4 LEDs |
| **probes** | 3x 74HC273 clocked by CLK^ | capture DB, AB-lo, AB-hi at the commit edge | - | - | 24 LEDs = "what was transferred in the last step" (live bus LEDs would show the *next* address after PC+/X+ while stopped in phase C) |

Datasheet facts relied on (all 74HC, rising-edge): 161 load and count are synchronous, /MR asynchronous, load overrides count, TC = CET & Q=1111; 377 /E is a synchronous clock enable; 273 /MR is asynchronous; **74HC191** (Nexperia datasheet): counts on CP^, parallel load is *asynchronous* (used only for reset), "CE LOW->HIGH transition only while CP is HIGH", "U/D change only while CE or CP is HIGH" - satisfied because SPCNT/SPDN change at C->D when CLK=1, and TC_lo changes only just after CLK^ (CLK=1). The TC->NAND carry avoids the clock-gated /RC output.

Why 161 counters for PC/AR/X (instead of 574 registers + an incrementer): load, increment and reset are all synchronous on the one commit edge and each counter drives its LEDs and buffers directly.

### 3.4 ALU: two SST39SF010A lookup ROMs (nibble-sliced)
| ROM | Address inputs (17) | Data outputs (8) |
|---|---|---|
| **ALU-L** | A0-3 = A[3:0]; A4-7 = DB[3:0]; A8 = Cflag; A9 = A[4] (for right shifts); A10-14 = ALUOP[4:0]; A15-16 = jumpers (table bank, normally 0) | D0-3 = R[3:0]; D4 = **c4** (carry / not-borrow out; the bit shifted out for right shifts; A3 for left shifts); D5 = **Zlo** (R[3:0]==0) |
| **ALU-H** | A0-3 = A[7:4]; A4-7 = DB[7:4]; A8 = c4; A9 = Zlo; A10 = Cflag; A11 = Vflag; A12-16 = ALUOP[4:0] | D0-3 = R[7:4]; D4 = **Z**; D5 = **C**; D6 = **N**; D7 = **V** |

/CE=/OE=GND on both (outputs always on; they only feed register D inputs, never a bus). R[7:0] -> A D-inputs; Z C N V -> F D-inputs. V is computed inside ALU-H (it knows c4 and the high nibble, hence the carries into and out of bit 7). Flags an op does not change are copied from the old-C / old-V inputs, so **FL always loads all four flags** and "which flags change" is pure table content.

**ALUOP codes (5 bits, 20 used)**: 00 PASSB (LDA/TXLA/PLA: R=B, ZN) | 01 ADD | 02 ADC | 03 SUB (also CMP) | 04 SBC | 05 AND | 06 OR | 07 XOR | 08 INC | 09 DEC | 0A NOT | 0B NEG | 0C SHL | 0D ROL | 0E SHR | 0F ROR | 10 ASR | 11 PASSA (TST) | 12 CLC | 13 SEC | 14-1F "poison": R=A5, flags=1111 (a wrong ALUOP is instantly visible on LEDs).
C after SUB/SBC/CMP: 1 = no borrow (A >= B unsigned). CMP = SUB with FL but without DD_A.

Why ROMs instead of 74HC283 + 74HC86 + muxes: 2 chips instead of ~12, all 20 ops including shifts/rotates and correct V, and the **same Python function generates the ROM image and the emulator's ALU**, so hardware and emulator cannot disagree. Each ROM is testable alone with DIP switches on its address pins and LEDs on its outputs. Cost: two ROM delays in series (c4/Zlo ripple), ~140 ns max (section 5).

### 3.5 Flag generation
Z, C, N, V come only from ALU-H D4-D7 and are registered in F on CLK^ when FL=1. No separate flag gates. F outputs feed the uROM address (branch decisions), ALU-L A8 / ALU-H A10 (old C), ALU-H A11 (old V), and 4 LEDs.

### 3.6 Address-bus sources
ASRC 00 = PC (the all-zero reset control word therefore shows PC on AB), 01 = AR, 10 = X, 11 = SP (AB = EF:SP). 74HC139 outputs -> /OE of the two 245s of the chosen source. The address bus never floats while the CPU owns it, so memory and the address decoder never see a floating address.

### 3.7 Moving 16-bit values over the 8-bit bus
- Into AR / X: two steps, low then high byte (DD_ARL/DD_ARH, DD_XL/DD_XH load only their half; the other half cannot count because its CEP=0 in that step).
- Into PC: only from AR, all 16 bits at once (PCLD). JMP/CALL/Bcc/RET/JPX build the target in AR first, so PC never holds a half-updated value (no confusing "PCL loaded, PCH not yet" state while single-stepping).
- Out of PC: PCH, PCL onto DB (CALL). Out of X: XL/XH (STX, PHX, TXLA/TXHA).
- **Readable onto DB**: MEM, A, XL, XH, PCL, PCH, SW. **Not readable** (LEDs and Arduino trace only): IR, AR, SP, F, STEP.

### 3.8 Datapath chip list
PC 4x161, AR 4x161, X 4x161, F 1x161, SP 2x191, A 1x377, IR 1x377, AB drivers 8x245, DB drivers 6x245 (A, XL, XH, PCL, PCH, SW), ALU 2x SST39SF010A, probes 3x273, glue 1x74HC00 (SP carry NAND + spares) = **37 ICs** (STEP counter and decoders are counted in section 4).

## 4. Control unit

### 4.1 Microcode ROM address (3x SST39SF010A, identical address wiring)
| uROM pin | A0-A3 | A4-A11 | A12 | A13 | A14 | A15 | A16 |
|---|---|---|---|---|---|---|---|
| signal | STEP[3:0] | IR[7:0] | Z | C | N | V | BANK jumper |

STEP in the low bits means a hex dump shows one instruction per 16-byte line. A16 = **BANK jumper**: two complete microcode versions live in each chip (bank 0 = known-good, bank 1 = experimental), switchable without reprogramming. Address space used per bank: 64K x 3 bytes. /CE = GND, /OE = MANUAL (panel switch; high = ROM outputs off).

### 4.2 Control word (24 bits, all active-high, latched in 3x 74HC273 on LCLK^ = C->D, /MR = /RESET_sync)
| ROM | Bit | Name | Meaning |
|---|---|---|---|
| uROM0 "bus" | 0-1 | ASRC | 0 PC, 1 AR, 2 X, 3 SP -> 74HC139 #AS |
| | 2-4 | DSRC | 0 none, 1 MEM, 2 A, 3 XL, 4 XH, 5 PCL, 6 PCH, 7 SW -> 74HC138 #DS |
| | 5-7 | DDST | 0 none, 1 IR, 2 A (from ALU), 3 XL, 4 XH, 5 ARL, 6 ARH, 7 spare (generator forbids) -> 74HC138 #DD |
| uROM1 "alu/mem" | 8-12 | ALUOP | section 3.4 |
| | 13 | FL | load Z C N V |
| | 14 | MEMW | memory/IO write this step (strobe made in phase A, section 5) |
| | 15 | MARK | scope-trigger test point + LED + Arduino trace marker (set on illegal opcodes; optionally on any step via a generator option) |
| uROM2 "sequencer" | 16 | PCINC | PC+1 |
| | 17 | PCLD | PC <- AR |
| | 18 | ARINC | AR+1 |
| | 19 | XINC | X+1 |
| | 20 | SPCNT | SP counts |
| | 21 | SPDN | direction: 0 = SP+1, 1 = SP-1 |
| | 22 | NEXT | STEP <- 0 at this commit |
| | 23 | HALT | stop in phase C after this step |

**All-zero word = harmless NOP** with ASRC=PC: this is what /RESET leaves in the latch, and what the generator puts nowhere else (unused steps get `HALT MARK NEXT`, so a missing NEXT or a bad opcode stops visibly instead of running wild). Bits are grouped so each ROM drives one physical area: uROM0 -> bus decoders, uROM1 -> ALU/memory, uROM2 -> counters.

Polarity fix-ups (1x 74HC04): /PCLD -> PC /LOAD, /FL -> F /LOAD, /NEXT -> STEP /LOAD, /SPCNT -> SP /CE_lo (2 spare inverters).

### 4.3 Decoders
- **#DS** 74HC138 (DSRC): Y1 = /MRD (memory read, to the memory module), Y2-Y7 = /OE of the A, XL, XH, PCL, PCH, SW 245s. Disabled by BUSACK.
- **#DD** 74HC138 (DDST): Y1 /DD_IR, Y2 /DD_A, Y3 /DD_XL, Y4 /DD_XH, Y5 /DD_ARL, Y6 /DD_ARH. These are **synchronous load enables** (377 /E, 161 /LOAD) - never clocks, so a decode glitch during D/A is harmless; they only have to be stable at CLK^.
- **#AS** 74HC139 half (ASRC): Y0-Y3 -> /OE pairs of PC/AR/X/SP address 245s. Disabled by BUSACK. (Other half used by the memory decoder.)

### 4.4 Step counter
74HC161 clocked by CLK (commit edge). Counts every cycle; /LOAD = NOT NEXT with D = 0000 makes the return to step 0 **synchronous** (no async-clear glitch, unlike the classic "decode step N -> /CLR" trick). /MR = /RESET_sync. 4 LEDs. Max 16 steps; the longest instruction (CALL, RET, LDX/STX abs) uses 5.

### 4.5 Fetch
One step, identical for all 256 opcodes x 16 flag values: `S0: ASRC=PC DSRC=MEM DDST=IR PCINC`. At CLK^ IR <- [PC], PC <- PC+1, STEP <- 1. During phase C the uROM address (new IR, STEP=1) settles, and at C->D the first execute word is latched. Every instruction therefore costs 1 + (execute steps) cycles; no separate "decode" step is needed because IR goes straight into the uROM address.

### 4.6 Conditional branches
Z, C, N, V are uROM address bits (A12-A15). For opcode B0+cc the generator evaluates the condition for each of the 16 flag combinations and writes either the **taken** sequence (S1 ARL<-[PC],PC+ / S2 ARH<-[PC],PC+ / S3 PCLD NEXT) or the **not-taken** sequence (S1 PC+ / S2 PC+ NEXT). No condition multiplexer, no flag-select logic, and signed conditions (N xor V) cost nothing. Flags never change inside a Bcc, so the address cannot shift mid-instruction. For all other opcodes all 16 flag copies are identical.

### 4.7 Reset
- Sources: power-on RC (10k/10uF) + RESET button -> 74HC14 Schmitt -> **reset synchronizer** (74HC74: async assert, release clocked on MCLK *falling* edge, two stages) -> /RESET_sync. Release therefore happens half an MCLK period away from any rising edge the phase counter uses.
- /RESET_sync does (all asynchronous, held as long as the button is held): Johnson counter forced to **phase C** (both /SET), control latch -> all-zero NOP, STEP=0, PC=0000, AR=0000, X=0000, F=0000, SP=FF (191 async load), BRK FF cleared, PS/2 READY cleared.
- After release: in RUN mode the next MCLK edge is C->D: the fetch word for step 0 is latched and the CPU fetches from **0000**. In STEP mode it waits in C for the STEP button. **SP starts at FF** (first push goes to EFFF). A and IR are undefined (emulator marks A as unknown).
- VGA counters are not reset (they self-recover within one frame; 74HC163 wraps).

### 4.8 Stop logic: RUN/STEP, HALT, breakpoint, BUSREQ (clock module, see 5.1 for the phase counter)
All stop sources are only honored in **phase C** (after a commit, before the next control word is latched):
```
STOP = BRQ_s | ( (HALT_L | BRK_L | (STEPMODE_s & (MICRO_sw | NEXT_L))) & !GO )
```
- HALT_L, NEXT_L = HALT and NEXT bits of the still-latched control word (they describe the step that just committed).
- **STEPMODE_s**: RUN/STEP toggle, 2-FF synchronized to MCLK. **MICRO_sw**: MICRO (stop every cycle) / INSTR (stop when the committed step had NEXT, i.e. after each whole instruction).
- **GO**: STEP/CONTINUE button -> 74HC14 RC debounce -> 74HC175 (sync1, sync2, prev) -> GO = sync2 & !prev = exactly **one MCLK period**, which lets exactly one cycle through. GO also continues after HALT or a breakpoint, so `HALT` (opcode 00) doubles as a software breakpoint.
- **BRK_L**: 2x 74HC688 compare AB with 16 DIP switches (/E = NOT BPEN); MATCH = NOR of the two /P=Q outputs; BRK FF (74HC74, clocked CLK^) D = MATCH & (DSRC==MEM | MEMW). It stops right after any **fetch, operand read or write** of that address (instruction breakpoint and data watchpoint with the same hardware). LED.
- **BUSREQ**: Arduino /BUSREQ (10k pull-up -> inactive when the Arduino is absent) -> 2-FF sync -> BRQ_s. BUSACK FF (MCLK): D = BRQ_s & STOP & Q1 & Q2, so BUSACK rises only once the CPU is *already* parked in C and falls on the same edge that lets the CPU leave C. BUSACK disables #DS and #AS (all CPU bus drivers and /MRD off); no register can load because CLK does not tick while parked. The Arduino then owns AB, DB, /ARD_RD, /ARD_WR (both pulled up, ANDed into the memory strobes, section 6). Protocol: assert /BUSREQ -> wait BUSACK -> drive -> **release all pins** -> deassert /BUSREQ.
- Indicators: LEDs for phase (Q1, Q2), STOP, WAIT, HALT, BRK, BUSACK, MARK.

### 4.9 Manual control panel (module test before microcode exists)
- MANUAL toggle (change only while stopped): uROM /OE = MANUAL; 3x 74HC245 (DIR strapped, /OE = NOT MANUAL) drive 3x 8-way DIP switches (10k pull-downs) onto the uROM data lines = control-latch inputs. A hand-set word therefore goes through **the same latch, decoders and timing** as real microcode.
- DATA switches: 8-way DIP -> 245 -> DB as DSRC=7 (SW).
- Example: set `DSRC=SW DDST=A ALUOP=PASSB FL`, data=0x80, press STEP -> A=80, N=1. Set `ASRC=PC DSRC=MEM DDST=IR PCINC` -> manual fetch.

### 4.10 Control-unit chip list
uROM 3x SST39SF010A, control latch 3x 74HC273, #DS/#DD 2x 74HC138, #AS 74HC139, STEP 74HC161, polarity 74HC04, manual panel 3x 74HC245 + 1 data-switch 245 (counted in datapath), breakpoint 2x 74HC688 + 74HC74 (BRK FF + 1 spare) + 74HC02 (MATCH NOR, ACCESS logic) = **18 ICs** (+ clock module, section 5).

## 5. Clocking and timing

### 5.1 Clock module
- **MCLK sources** (74HC153 4:1 mux, selected by a 2-pole switch; *change only while STOPPED* - while parked in C the phase counter's next state equals its present state, so a runt pulse during switching is harmless): (0) **4.000 MHz crystal oscillator can** (5 V, DIP-14/8 footprint; 8 MHz can for a 2 MHz CPU), (1) **NE555** astable 1 Hz - 2 kHz (pot) -> 74HC14, (2) **Arduino pin** (trace mode), (3) spare.
- **Phase counter**: 2-FF Johnson counter (74HC74 on MCLK^). States Q1Q2: A=00 -> B=10 -> C=11 -> D=01 -> A. Next-state logic (one 74HC00, 4 NANDs):
  - `Q1' = !Q2 | (STOP & Q1)` -> holds in **C** while STOP=1 (Q1=1 only in B and C; in B the first term already forces 1)
  - `Q2' = Q1 | (WAIT & Q2)` -> holds in **D** while WAIT=1 (VRAM write outside the window, section 6)
  - /RESET_sync drives both /SET -> reset parks the counter in C.
- **Derived signals** (all glitch-free because Johnson neighbours differ in one bit): CLK = Q2 (rises B->C), LCLK = /Q1 (rises C->D), WSTB = NOR(Q1,Q2) = phase A, PHB = Q1 & !Q2 (phase B, used for the PS/2 read-clear strobe).
- **Fan-out**: CLK drives ~22 clock pins on 5+ boards. It goes through one **74HC245 used as a clock buffer** (DIR strapped, /OE=GND), one output per module (<= 5 loads each), each with a **47 ohm series resistor** at the buffer pin (damps ringing on breadboard wires). Star wiring, short dedicated clock wires with a ground wire alongside. All outputs from one chip -> skew ~2-5 ns, far below the minimum ~15 ns clock-to-bus-to-D path, so no hold violations. LCLK only feeds the 3 control latches + BUSACK logic on the control board (short).
- Decoupling: 100 nF ceramic at every IC, 10-47 uF electrolytic per breadboard, power injected at both ends of every rail pair.

### 5.2 One CPU cycle (4 MCLK periods; 250 ns each at 1 MHz)
| Edge / phase | What happens |
|---|---|
| **C->D** (LCLK^) | Control latch loads the next word (only if STOP=0). CLK stays HIGH (74HC191 rule satisfied). |
| phase **D** | ASRC/DSRC decoders switch; address and bus source settle; memory access starts; WAIT is evaluated at the D->A edge. |
| **D->A** (CLK falls) | Nothing is clocked on this edge (except the reset synchronizer, on MCLK falling). |
| phase **A** | If MEMW: **/WE low for exactly this phase**. Address has been stable for a whole phase before, data source too. |
| **A->B** | /WE returns high. |
| phase **B** | Address, data, ALU and flags remain stable for a full phase after /WE rose (hold margin = 250 ns); read data and ALU results settle. |
| **B->C** (CLK^) | **Every CPU register commits** (A, IR, F, PC, AR, X, SP, STEP, probes, BRK FF), only where its synchronous enable is active. |
| phase **C** | New STEP/IR/flags propagate through the uROM. STOP sources are evaluated at C->D. A stopped machine always rests here. |

### 5.3 RAM /WE generation and why it is safe
`/MWR = NAND(MEMW_L, WSTB)`; on the memory board `/WE_RAM = OR(AND(/MWR, /ARD_WR), /RAMSEL)` (same for VRAM and the output port). AS6C62256-55 requirements vs what this design gives at 1 MHz:
| Parameter | Spec (min) | Provided |
|---|---|---|
| tAS address setup to /WE low | 0 ns | >= 250 ns minus address path (~95 ns max) = 155 ns |
| tWP /WE pulse width | 45 ns | 250 ns (125 ns at 2 MHz) |
| tDW data setup to /WE high | 25 ns | ~400 ns |
| tWR, tDH address/data hold after /WE high | 0 ns | 250 ns (whole phase B) |
/WE can never be asserted while the address changes because the address only changes at C->D and CLK^ edges, and phase A is separated from both by at least one full MCLK period. The generator forbids DSRC=MEM in a MEMW step, so RAM /OE is never active during a write.

Bus turnaround: when DSRC changes at C->D (e.g. MEM -> A) the old driver needs ~20 ns to release while the new one enables; the overlap is a few ns, low current, and at least 200 ns away from any sampling edge.

### 5.4 Critical paths (74HC at 5 V; "max" = 25 C datasheet max at 4.5 V, "typ" = typical)
| Path | Elements | max | typ | Budget 1 MHz | Budget 2 MHz |
|---|---|---|---|---|---|
| **Read + ALU into A/F** (LDA abs, ADD (X)) | 273 clk->Q 30 + 139 35 + 245 /OE 30 + addr decode 138 35 + ROM tCE 70 + ALU-L 70 + ALU-H 70 + 377 setup 20 | **360** | ~200 | D+A+B = 750 | 375 |
| **uROM** | CLK^ -> 161/377 Q 35 + uROM tAA 70 + 273 setup 20 | **125** | ~85 | C = 250 | 125 |
| **WAIT** (VRAM gate) | 273 30 + 139 35 + 245 30 + 138 35 + 2 gates 40 + 74 setup 20 | **190** | ~105 | D = 250 | 125 |
| IR fetch | as read path without ALU (IR D from DB) | 200 | ~120 | 750 | 375 |
| RAM write | see 5.3 | - | - | ok | ok |
| 16-bit counter carry (TC ripple 4 stages) | 40 + 3x25 + setup 20 | 135 | ~60 | 1000 (whole cycle) | 500 |

**Verdict**: 1 MHz has >= 2x margin on every path even at worst-case datasheet values. **2 MHz** (8 MHz MCLK) works with typical parts (all paths <= 85% of budget at typ) but the uROM and WAIT paths have zero worst-case margin; it is a "try it and scope it" option, not a guarantee. Should 2 MHz be needed, the cure is a 6-phase Johnson counter (one 74HC74 more, 12 MHz MCLK -> 2 MHz), giving those two paths 2 phases each.

### 5.5 Clock-module chip list
Crystal oscillator can (1), NE555 (1), 74HC14 (debounce + 555 squaring), 74HC153 (source select), 74HC74 (Johnson), 74HC00 (Johnson next-state), 74HC74 (reset synchronizer), 2x 74HC175 (GO sync/edge, STEPMODE sync, BUSREQ sync, BUSACK FF), 74HC08 + 74HC32 + 74HC00 + 74HC02 (STOP, /GO, WSTB, PHB, /MWR, WAIT), 74HC245 (CLK buffer) = **14 ICs** incl. oscillator and 555. (VWR/READY synchronizer 74HC175 #SYNC3 sits on the memory board, section 6.)

## 6. Memory and I/O

### 6.1 Address decode (memory board)
| Signal | Logic | Chip |
|---|---|---|
| /ROMSEL | = A15 (ROM when A15=0) | wire |
| /Y7 (F000-FFFF) | 74HC138 #MEM: C,B,A = A14,A13,A12; G1 = A15; /G2A=/G2B=GND -> Y7 | 74HC138 |
| /RAMSEL (8000-EFFF) | NAND(A15, /Y7) | 74HC00 gate |
| /VRAMSEL (F000-F7FF), /IOSEL (F800-FFFF) | 74HC139 half #2: /G = /Y7, A = A11, B = GND -> Y0 = /VRAMSEL, Y1 = /IOSEL | 74HC139 (other half of #AS) |
| /RD | AND(/MRD, /ARD_RD) (Arduino line pulled up) | 74HC08 |
| /WR | AND(/MWR, /ARD_WR) (pulled up) - /MWR is the phase-A strobe from 5.3 | 74HC08 |

- **ROM** SST39SF010A: A0-A14 = AB, **A15-A16 = 2 jumpers = 4 program banks** (e.g. bank 0 monitor+tests, bank 1 Snake), /CE = /ROMSEL, /OE = /RD, /WE = VCC (10k pull-up; never written in circuit). (AT28C256 is a drop-in alternative with A15/A16 pins absent.)
- **RAM** AS6C62256-55: A0-A14 = AB (8000-EFFF -> chip 0000-6FFF; chip 7000-7FFF unused), /CE = /RAMSEL, /OE = /RD, /WE = /WR (CE does the selection; /WE only falls in phase A when AB is long stable).
- Memory data pins connect straight to DB (their outputs are the "MEM" bus source; /OE comes only from /RD).

### 6.2 I/O registers (F800-FFFF, A2..A0 decoded, mirrored every 8 bytes)
Two 74HC138: **#IOR** (A,B,C = A0,A1,A2; /G2A = /IOSEL, /G2B = /RD) -> read enables; **#IOW** (G1 = MEMW_L, /G2A = /IOSEL, /G2B = GND) -> *synchronous* write enables for output latches that are clocked by CLK^ (no strobe-clocked latches; the write enable is decoded from the latched control word + stable address).
| Addr | R/W | Name | Bits | Hardware |
|---|---|---|---|---|
| F800 | R | KBD_DATA | PS/2 scan-code byte. **Reading clears READY** and releases the keyboard. | 74HC245 from the PS/2 shift register |
| F801 | R | STATUS | b0 KBD_READY, b1 VWR (VRAM write window open = vertical blanking), b2-b6 read 0, b7 BOOTRAM (Arduino line, 10k pull-down) | 74HC245 (inputs from 2-FF synchronizers) |
| F802 | R | SWITCHES | 8 user DIP switches (game speed / test select) | 74HC245 + 10k pull-ups |
| F804 | W | LEDS | 8 LEDs | 74HC377, /E = #IOW Y4, CP = CLK |
| F805 | W | SEG0 | 7-seg digit 0 segments a-g,dp (software hex table) | 74HC377 |
| F806 | W | SEG1 | 7-seg digit 1 segments | 74HC377 |
| F803, F807 | - | reserved | reads 00 (DB pull-downs) | - |
Software contract: `poll STATUS.b0 until 1, then read KBD_DATA` (one byte per read; break codes F0 xx arrive as two bytes). `wait STATUS.b1 == 0, then == 1` = start of a frame's write window (also the 60 Hz game tick).

### 6.3 VRAM write path and VBLANK-only gating
- VGA timing ROM produces two registered window bits (section 7): **VMUX** = lines 481-523 (VRAM address/data belong to the CPU) and **VWR** = lines 482-522 (CPU may *start* a write). VWR is nested in VMUX with one full line (31.8 us) of guard on each side.
- VWR -> 2-FF synchronizer on MCLK (74HC175 #SYNC3 also syncs READY) -> **VWR_s** -> STATUS.b1 and the stall logic.
- **Stall instead of drop**: `WAIT = MEMW_L & VRAMSEL & !VWR_s` holds the phase counter in **D** (section 5.1) until the window opens; then phase A writes. A write is therefore never lost and never lands outside the window, and the WAIT LED shows when software is too slow. Software is still expected to poll VWR (a stall can last up to 15 ms).
- VRAM = AS6C62256 (same part as RAM; A11-A14 grounded) on the VGA board:
  - Address: 3x 74HC157, select = VMUX: 1 -> CPU AB[10:0], 0 -> VGA {row[4:0], col[5:0]}.
  - Data in: DB -> 74HC245 (DIR strapped) -> VRAM D0-7; /OE_245 = NAND3(MEMW_L, VRAMSEL, VWR_s) (driven for the whole write step, before and after the /WE pulse -> ample setup/hold).
  - VRAM /OE = VMUX (outputs off while the CPU owns it -> no fight with the 245), /CE = GND, /WE = OR(/WR, /VRAMSEL).
  - Timing argument: VWR_s=1 at the D->A edge implies VWR was 1 at most 2 MCLK (0.5 us) earlier, hence VMUX stays 1 for >= 31 us more; the write ends within 0.25 us. Same at the window start. No VGA-domain signal is used combinationally on the CPU side.
- The CPU cannot read VRAM (write-only by design; Snake keeps its own board array in RAM).

### 6.4 PS/2 keyboard receiver (own clock domain: the free-running 4 MHz crystal oscillator OSC, so it keeps working while the CPU is stepped or on the 555)
| Function | Parts | Detail |
|---|---|---|
| Line interface | 4.7k pull-ups on KCLK/KDAT, 74HC14 | Schmitt inputs clean the slow open-collector edges; mini-DIN-6 socket. |
| Sync + edge detect | 74HC175 on OSC^ | FF0/FF1 = 2-stage KCLK sync, FF2 = previous, FF3 = KDAT sample. **FALL** = FF2 & !FF1 (1 OSC period per KCLK falling edge), gated with !READY. KDAT changes on KCLK rising and is sampled >= 5 us later -> 1 FF is enough. |
| Shift register | 2x 74HC377 as a 16-bit right-shift register (Dn = Qn+1, D15 = KDAT_s, /E = NOT FALL) | After the 11th shift: Q15 = stop, Q14 = parity, **Q13..Q6 = d7..d0**, Q5 = start. |
| Bit counter | 74HC163, ENP=ENT=FALL, D = 0101 | Counts 5 (start) ... 15 (stop). TC (= FALL & count 15) marks the stop bit. /LOAD = NOR(TC, TIMEOUT) -> reload 5. |
| Framing / resync | 74HC4040 clocked by !OSC, MR = !KCLK_s | Counts only while KCLK is high; **TIMEOUT = Q10** (256 us idle). Any partial frame (plug-in, glitch, missed edge) is discarded and the counter reloaded to 5. Normal KCLK high time is <= 50 us. |
| READY flag | 74HC74 (OSC) + glue | Set at TC if KDAT_s=1 (stop) and Q6=0 (start, before the last shift). Async clear by **/CLRRDY = NAND(KBD_DATA read, PHB)** (phase-B pulse, glitch-free because the address and DSRC are stable in B) and by /RESET. |
| Keyboard inhibit | 2N7000 (gate = READY) pulls KCLK low | While READY=1 the keyboard holds further bytes in its own buffer, so the byte cannot be overwritten or change while the CPU reads it; FALL is gated off while READY=1, so the self-made low edge is ignored. Releasing KCLK starts the next byte >= 50 us later. |
| CPU side | READY -> 2-FF sync (#SYNC3) -> STATUS.b0; Q13..Q6 -> 74HC245 -> DB at F800 | Data is frozen from the moment READY is set, 2+ MCLK before the CPU can see READY_s. |
Parity is not checked in v1 (start/stop framing + timeout resync are enough for a keyboard on a 30 cm cable); the parity bit is available at Q14 for v2.

## 7. VGA module (40x30 text, monochrome with DIP-selectable colour)

### 7.1 Clocks
- **25.175 MHz oscillator can** -> 74HC74 toggle FF -> **DCLK = 12.5875 MHz** (one DCLK = one font pixel = two 640-mode pixels).
- **DOT** counter: 74HC163 free-running on DCLK; index = Q[2:0] (0..7 per character). **CCLK = DOT.QC** (rises at index 3->4, mid-character; a clean flip-flop output, 1.573 MHz).
- **/LD7** = 74HC74 FF on DCLK, D = NAND3(QC, QB, /QA) (index 6) -> Q low exactly during index 7. It is the synchronous load enable for everything that changes at the character boundary. Registered (not decoded combinationally) so the 166/377 enable setup has a full DCLK period.

### 7.2 Counters (fully synchronous, on CCLK)
| Counter | Parts | Range | Control (straight from timing-ROM outputs, stored active-low where needed: they are synchronous inputs sampled one whole character later, so ROM glitches do not matter) |
|---|---|---|---|
| HCHAR | 2x 74HC163 (6 bits) | 0..49 | /CLR = /LINE_END (ROM entry hchar=49) |
| VLINE | 3x 74HC163 (10 bits) | 0..524 | ENP = LINE_END, ENT chained via RCO; /CLR = /FRAME_END (entry line 524, hchar 49) |
Self-recovering after power-up: table entries for hchar 50-63 have LINE_END, for lines 525-1023 FRAME_END.

### 7.3 Timing ROM (SST39SF010A #VT)
Address A0-A5 = HCHAR, A6-A15 = VLINE, A16 = jumper (alternative timing table, e.g. a test-pattern mode). Generated by Python from the VGA numbers. Outputs:
| D | Signal | Active in table (char slot n 0..49, line 0..524) |
|---|---|---|
| 0 | /HSYNC | low for n = 41..46 (48 dots) |
| 1 | /VSYNC | low for lines 490..491 |
| 2 | DISPEN | high for n <= 39 and line <= 479 (320 x 480 dots) |
| 3 | LINE_END | n = 49 |
| 4 | /LINE_END | n = 49 |
| 5 | /FRAME_END | line 524 and n = 49 |
| 6 | VMUX | lines 481..523 (CPU owns VRAM) |
| 7 | VWR | lines 482..522 (CPU may start writes; status bit) |
Horizontal: 40 visible chars (320 dots) + 1 front porch (8) + 6 sync (48) + 3 back porch (24) = 50 chars = 400 dots. Vertical: 480 + 10 + 2 + 33 = 525. Both syncs negative.

### 7.4 Character pipeline (all registers on DCLK with /E = /LD7, i.e. at the character boundary)
| When | Action |
|---|---|
| index 4 of slot S (CCLK^) | HCHAR <- n (VLINE may step). VRAM address and timing-ROM address change; ~4 dots to settle. |
| boundary S/S+1 | **CH** (74HC377) <- VRAM[row=VLINE[8:4], col=n]; **T1** (74HC377) <- /HSYNC, /VSYNC, DISPEN, VMUX, VWR of entry n. |
| slot S+1 | **FONT** ROM (SST39SF010A): A0-A2 = VLINE[3:1] (font row; bit 0 doubles lines), A3-A10 = CH, A11-A16 = jumpers (32 font banks). |
| boundary S+1/S+2 | **74HC166** loads the glyph row (/PE = /LD7; font bit 7 = leftmost pixel wired to input H); **T2** (74HC377) <- /HSYNC, /VSYNC, DISPEN from T1. |
| slot S+2 | 166 shifts the 8 pixels out of QH; syncs and DISPEN are exactly aligned (both took two boundaries). |
No timing-table offsets are needed: pixel data and sync/blank pass through the same number of boundary registers. Nothing samples a signal on the same edge that changes it (counters change at index 4, registers load at index 7->0).
- VLINE changes at index 4 while CH holds the code of char 49 (blank), so the font-row change can only affect an invisible character.

### 7.5 Output stage
- **Video**: 74HC11 (triple 3-input AND): R = QH & DISPEN_T2 & SW_R, G = ... & SW_G, B = ... & SW_B (3 DIP switches choose the text colour; DISPEN forces RGB to 0 in blanking). One gate per colour so each output sources only ~9 mA.
- **DAC**: 470 ohm series per colour into the monitor's 75 ohm: 5 V x 75/(470+75) = 0.69 V (~0.63 V with HC output droop) - within the 0.7 V full scale. (v2 2-bit colour: 470 ohm + 1 k per channel.)
- **Syncs**: T2 /HSYNC, /VSYNC -> 100 ohm series -> DE-15 pins 13/14. GND pins 5,6,7,8,10.
- **VRAM port** (section 6.3): VRAM /OE = VMUX (T1), address mux 3x 74HC157 select = VMUX.

## 9. C mapping

### 9.1 Supported C subset (compiler written in Python)
- Types: `char`/`unsigned char` (8-bit), `int`/`unsigned int` (16-bit, two's complement), pointers (16-bit) to char/int, 1-D global arrays, string literals, `const` tables (placed in ROM), `volatile` (memory-mapped I/O). No float, no struct in v1 (struct is a v2 option: fixed field offsets are easy with static allocation).
- Statements: `if/else`, `while`, `do/while`, `for`, `break`, `continue`, `return`, blocks.
- Operators: `+ - & | ^ ~ ! << >>` (shift by constant inline, by variable via loop), `== != < <= > >=` (signed and unsigned picked from the operand types), `&& ||` (short-circuit), `++ --` (pre/post), compound assignment, unary `*` and `&` (of globals). `* / %` via runtime routines (shift-add / shift-subtract, ~150-400 cycles); constant powers of two become shifts/masks.
- Functions: up to 4 parameters, `char`/`int`/pointer return, **no recursion** (the compiler builds the call graph and rejects cycles), no function pointers in v1 (possible later: push return address + JPX = 12 cycles).
- I/O: `#define KBD_DATA (*(volatile char*)0xF800)` etc.; a tiny runtime: `wait_vblank()`, `getkey()`, `putc_at()`, `mul16`, `divmod16`, `rand16` (LFSR).

### 9.2 Calling convention and storage (choice: **static frames**, "compiled stack")
- Every function gets a fixed RAM frame: `f_p0..f_p3` (parameters), `f_l*` (locals), `f_t*` (expression temporaries). The compiler overlays frames of functions that can never be active at the same time (call-graph colouring), so RAM use stays close to the deepest call chain.
- **Caller** evaluates each argument directly into the callee's parameter slots (absolute STA), then `CALL f`. **Return value**: `char` in A, `int`/pointer in the fixed pseudo-register `__rv` (2 bytes). A and X are caller-saved (any call may clobber them); nothing is callee-saved.
- Hardware stack (EF00-EFFF) holds only return addresses and occasional PHA/PHX saves -> 128 call levels, far beyond Snake's ~6.
- Why static instead of a stack frame: the ISA deliberately has no SP-relative or indexed mode (no 16-bit address adder, section 1). With static frames **every local is an absolute address**: one 3-byte, 4-cycle instruction per byte access, and every access is visible in the trace at a fixed, symbol-mapped address (the Python emulator/trace viewer can print `snake_len = 5` straight from the bus log - a large debugging win). The price - no recursion, no reentrancy - is irrelevant for Snake, and there are no interrupts.
- Memory layout: 8000-80FF runtime pseudo-registers and temporaries, 8100-... globals then overlaid frames, heap none, EF00-EFFF stack. Snake's board array (40x30 = 1200 B) lives in RAM.

### 9.3 Code patterns (cycles at 1 cycle = 1 us @ 1 MHz; counts from table 2.2)
**(a) `int a = b + c;` (16-bit globals)**
```
LDA b      ; 4
ADD c      ; 4   C = carry out of low byte
STA a      ; 4
LDA b+1    ; 4   loads do not touch C
ADC c+1    ; 4
STA a+1    ; 4
```
18 bytes, **24 cycles**.

**(b) `*p = x;` (char *p, char x globals)**
```
LDX p      ; 5   X <- 16-bit pointer (little-endian)
LDA x      ; 4
STA (X)    ; 2
```
7 bytes, **11 cycles**. (`p++` on a pointer = `LDX p / INX / STX p` = 12 cycles; `*p++ = x` keeps p in X and uses `STA (X+)`.)

**(c) `if (x < y) {...}` (signed 16-bit)**
```
LDA x      ; 4
CMP y      ; 4   low bytes: only C (borrow) matters
LDA x+1    ; 4   C preserved
SBC y+1    ; 4   high byte with borrow: N and V describe the full 16-bit x-y
BGE skip   ; 3 not taken / 4 taken   (N == V  -> x >= y)
  ... then-part ...
skip:
```
15 bytes, **19-20 cycles**. `x > y` is emitted as `y < x` (operands swapped), `x <= y` as `!(y < x)`; unsigned uses BLO/BHS; `==`/`!=` compare both bytes with CMP + BNE.

**(d) `r = f(a, b);` with `int f(int u, int v) { return u + v; }`**
```
; caller                              ; callee
LDA a     / STA f_u                   f:  LDA f_u      ; 4
LDA a+1   / STA f_u+1                     ADD f_v      ; 4
LDA b     / STA f_v                       STA __rv     ; 4
LDA b+1   / STA f_v+1    ; 8 x 4 = 32     LDA f_u+1    ; 4
CALL f                   ; 5              ADC f_v+1    ; 4
LDA __rv  / STA r                         STA __rv+1   ; 4
LDA __rv+1/ STA r+1      ; 4 x 4 = 16     RET          ; 5   -> 29
```
Caller 53 + callee 29 = **82 cycles** (~82 us). When an argument is an expression the compiler computes it straight into the parameter slot, so there is no extra copy.

**(e) Loop writing a string to VRAM: `while (*s) *d++ = *s++;` (s = char* in ROM/RAM, d = VRAM pointer)**
```
      LDX s        ; 5   source pointer lives in X
loop: LDA (X+)     ; 2   A = *s++ ; sets Z
      BEQ done     ; 3   (4 when taken)
      PHX          ; 3   save source pointer
      LDX d        ; 5
      STA (X+)     ; 2   *d++ = A  (VRAM; stalls in phase D if outside the window)
      STX d        ; 5
      PLX          ; 4
      JMP loop     ; 4
done: STX s        ; 5   (only if s is used afterwards)
```
**28 cycles per character**: a 40-character line takes ~1.1 ms, i.e. fits in one 1.30 ms vertical-blank write window. The program calls `wait_vblank()` first (`LDA F801 / AND #2 / BNE` then `... / BEQ`, i.e. wait for the window to close then reopen); if a string is longer, the hardware stall makes the code correct anyway, just slower.
Screen clear (fixed fill value, one pointer): `LDX #F000`, then per row 64 x `STA (X+)` unrolled + a row counter in RAM = ~144 cycles/row -> 4.3 ms = 4 frames.

**Snake budget**: one move per 6-10 frames (100-170 ms). Per move: read key (~20 cycles), update head/tail in the 1200-byte board array (~18 cycles per indexed access, ~300 cycles total), 2-3 VRAM cell writes (~60 cycles), collision/food check and LFSR (~300 cycles) -> ~1,000 cycles = 1 ms per move, i.e. < 1 % of the CPU at 1 MHz. Even the 555 at a few kHz plays a (slow) game, which is useful for debugging.

### 9.4 Instruction-set facts the compiler relies on
Loads, logic ops, INC/DEC, TXLA/TXHA do not change C or V (multi-byte arithmetic chains survive interleaved loads); CMP sets C = "no borrow"; BLT/BGE use N xor V; INX is a full 16-bit increment; `(X+)` post-increments all 16 bits; all control transfers are absolute (no branch-range limits for the code generator).

## 10. Risks, omissions, early prototypes

### 10.1 Risks (most serious first) and mitigations
| # | Risk | Mitigation in this design | Fallback |
|---|---|---|---|
| 1 | **Double clocking / ringing** on long breadboard clock wires | One commit edge per cycle; CLK through a dedicated 245 buffer with 47 ohm series resistors, star-wired; control word changes on a different edge 1/4 cycle later; 100 nF per IC | run MCLK at 2 MHz (CPU 500 kHz); everything is edge-count-correct at any speed |
| 2 | **Intermittent contacts** in ~2,000 jumpers | Every register on LEDs, probe latches, manual control word, BRK/watchpoint, Arduino trace diff vs emulator localizes a bad wire to one step and one signal | keep each module testable alone; re-seat chips; buy quality boards |
| 3 | **VGA dot-rate logic** (12.6 MHz, 74HC near datasheet max) | /LD7 registered, nothing samples on the edge that changes it, 4-dot settling for ROM/VRAM | separate board group with its own power feed; scope DCLK, /LD7, QH first |
| 4 | **8 flash chips to (re)program** | BANK jumpers (microcode: 2 versions, program ROM: 4 banks, font: 32 banks) cut reprogramming; ZIF/turned-pin sockets protect breadboard contacts | keep a known-good set labelled |
| 5 | **Power drop** across ~30 boards (0.6-0.8 A) | feed every rail pair from a bus bar; 3 A supply; measure >= 4.75 V at the farthest chip | - |
| 6 | **Software volume** for 2 people (generator, emulator, assembler rules, compiler) | isa.yaml is the single source; the Python emulator and ROM images come from the same functions; the compiler targets a small, regular ISA with absolute addressing only | drop `* / %` and structs |
| 7 | One pointer register -> copies cost ~28 cycles/byte | measured to be irrelevant for Snake (< 1 % CPU) | v2: second pointer register Y (8 chips) |
| 8 | 2 MHz not guaranteed (uROM and WAIT paths) | 1 MHz has >= 2x worst-case margin | 6-phase counter (section 5.4) |
| 9 | Keyboard compatibility (many "PS/2" keyboards are USB-only with adapters) | buy a genuine PS/2 keyboard now; receiver is RX-only + inhibit | - |
| 10 | Pricier / scarcer DIP parts in Turkey (74HC377 ~65 TL, 74HC688 ~80 TL, 74HC166 ~53 TL) | order early with spares; 377 can be replaced by a pair of 74HC161 used as registers (sync /LOAD, no count) | - |

### 10.2 Deliberately left out (v1)
Interrupts; indexed / SP-relative addressing and the 16-bit address adder they need; a second pointer register; relative branches; reading VRAM, SP, F or AR back; hardware multiply/divide; colour attributes per character; sound; host-to-keyboard commands (keyboard LEDs, typematic) and parity checking; recursion and function pointers in C; in-circuit flash programming; GAL/CPLD glue (everything is 74HC + ROM tables); dual-port VRAM or cycle stealing (writes only in vertical blank, with a hardware stall).

### 10.3 Prototype during the simulation phase (Nov 2026 - Jan 2027, small parts order now)
1. **Clock + one register**: oscillator, Johnson counter, CLK buffer, one 74HC161 and one 245 with 20 cm wires; scope edge quality, verify no double counting over 10^6 cycles (count with a second 161 chain), single-step and GO.
2. **Flash workflow**: program an SST39SF010A with the chosen programmer (TL866II+/T48), read it back on a breadboard with DIP switches -> doubles as the ALU-ROM test.
3. **VGA timing** on the actual demo monitor: oscillator + counters + timing ROM -> monitor locks to 640x480 (monitors are picky; test early), then the font path with VRAM replaced by DIP switches (whole screen of one character).
4. **PS/2 receiver** with LEDs on the shift register and READY: verify framing, inhibit and resync with the real keyboard.
5. **SRAM write** with the phase-A strobe at 1 MHz and with the Arduino-driven MCLK.
6. **Arduino adapter**: BUSREQ/BUSACK handshake, RAM load and readback, trace rate (expected ~5-20 kHz CPU clock while logging over 2 Mbaud serial).
